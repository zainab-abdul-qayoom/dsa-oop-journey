# Phase 1: Time and Space Complexity

This phase covers the fundamentals of analyzing the efficiency of algorithms. The goal is to understand how an algorithm's **time and memory requirements change as the input size grows**.

This is the foundation for analyzing DSA solutions during coding practice and technical interviews.

---

## 📚 Topics Covered

### 1. Time Complexity

Time Complexity describes how the running time of an algorithm grows with the input size `n`.

We use **Big-O notation** to describe this growth.

Common complexities:

| Complexity   | Meaning      |
| ------------ | ------------ |
| `O(1)`       | Constant     |
| `O(log n)`   | Logarithmic  |
| `O(n)`       | Linear       |
| `O(n log n)` | Linearithmic |
| `O(n²)`      | Quadratic    |
| `O(2ⁿ)`      | Exponential  |

A useful order to remember:

```text
O(1)
↓
O(log n)
↓
O(n)
↓
O(n log n)
↓
O(n²)
↓
O(2ⁿ)
```

---

## 2. Space Complexity

Space Complexity describes how much **extra memory** an algorithm uses as the input size grows.

Example:

```java
static void printNumbers(int n) {
    for (int i = 0; i < n; i++) {
        System.out.println(i);
    }
}
```

The loop runs `n` times, but it only uses a fixed number of variables.

```text
Time  = O(n)
Space = O(1)
```

### Important distinction

**Time Complexity:** How much work does the algorithm perform?

**Space Complexity:** How much extra memory does the algorithm require?

A loop running `n` times does **not** automatically mean `O(n)` space.

---

# 🔍 3. Basic Big-O Examples

## O(1) — Constant

```java
int first = arr[0];
```

Only one operation is performed regardless of the size of the array.

```text
Time = O(1)
Space = O(1)
```

---

## O(n) — Linear

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
```

The loop runs `n` times.

```text
Time = O(n)
Space = O(1)
```

---

## O(n²) — Quadratic

```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i + j);
    }
}
```

The outer loop runs `n` times and the inner loop runs `n` times for each outer iteration.

```text
n × n = n²

Time = O(n²)
Space = O(1)
```

---

## O(log n) — Logarithmic

```java
int i = 1;

while (i < n) {
    System.out.println(i);
    i = i * 2;
}
```

The value doubles:

```text
1 → 2 → 4 → 8 → 16 → ...
```

The number of iterations is logarithmic.

```text
Time = O(log n)
Space = O(1)
```

### Easy rule

When a value is repeatedly **doubled or halved**, think:

```text
O(log n)
```

---

# 🔗 4. O(n log n)

Example:

```java
for (int i = 0; i < n; i++) {

    int j = 1;

    while (j < n) {
        System.out.println(i + j);
        j = j * 2;
    }
}
```

Outer loop:

```text
O(n)
```

Inner loop:

```text
O(log n)
```

Because they are nested:

```text
O(n) × O(log n)

= O(n log n)
```

Space:

```text
O(1)
```

---

# ➕ 5. Separate Loops

Consider:

```java
for (int i = 0; i < n; i++) {
    System.out.println(i);
}

for (int j = 0; j < n; j++) {
    System.out.println(j);
}
```

Each loop is `O(n)`.

Because they are separate:

```text
O(n) + O(n)
= O(2n)
= O(n)
```

Therefore:

```text
Time = O(n)
Space = O(1)
```

### Remember

```text
Nested loops → usually multiply

n × n = O(n²)

Separate loops → add

n + n = O(n)
```

# 🔁 6. Recursion

Recursion occurs when a function calls itself.

Example:

```java
static void fun(int n) {

    if (n == 0) {
        return;
    }

    System.out.println(n);

    fun(n - 1);
}
```

The calls look like:

```text
fun(5)
  ↓
fun(4)
  ↓
fun(3)
  ↓
fun(2)
  ↓
fun(1)
  ↓
fun(0)
```

There are approximately `n` recursive calls.

Therefore:

```text
Time = O(n)
Space = O(n)
```

### Why is space O(n)?

Recursive calls remain on the **call stack** until they return.

The deeper the recursion goes, the more stack memory is required.

### Basic rule

```text
Number of calls → Time

Maximum recursion depth → Space
```

---

# 🔄 7. Recursive vs Iterative

## Iterative

```java
static void printNumbers(int n) {

    for (int i = 0; i < n; i++) {
        System.out.println(i);
    }
}
```

```text
Time  = O(n)
Space = O(1)
```

## Recursive

```java
static void printNumbers(int n) {

    if (n == 0) {
        return;
    }

    System.out.println(n);
    printNumbers(n - 1);
}
```

```text
Time  = O(n)
Space = O(n)
```

Both take `O(n)` time, but the recursive version uses additional call-stack space.

---

# 🧮 8. Fibonacci Complexity

## Iterative Fibonacci

```java
static int fibonacci(int n) {

    int a = 0;
    int b = 1;

    for (int i = 0; i < n; i++) {
        int temp = a + b;
        a = b;
        b = temp;
    }

    return a;
}
```

```text
Time  = O(n)
Space = O(1)
```

---

## Recursive Fibonacci

```java
static int fibonacci(int n) {

    if (n <= 1) {
        return n;
    }

    return fibonacci(n - 1) + fibonacci(n - 2);
}
```

The function creates two recursive branches:

```text
             fib(n)
            /      \
       fib(n-1)   fib(n-2)
          /  \       /  \
        ...  ...   ...  ...
```

For this basic recursive implementation:

```text
Time  = O(2ⁿ)
Space = O(n)
```

### Comparison

| Approach            |    Time |  Space |
| ------------------- | ------: | -----: |
| Iterative Fibonacci |  `O(n)` | `O(1)` |
| Recursive Fibonacci | `O(2ⁿ)` | `O(n)` |

This shows why two correct algorithms can have very different efficiency.

# 🔎 9. Binary Search

Binary Search works on a **sorted array**.

```java
static int binarySearch(int[] arr, int target) {

    int start = 0;
    int end = arr.length - 1;

    while (start <= end) {

        int mid = (start + end) / 2;

        if (arr[mid] == target) {
            return mid;
        }
        else if (arr[mid] < target) {
            start = mid + 1;
        }
        else {
            end = mid - 1;
        }
    }

    return -1;
}
```

After each iteration, the search space is approximately divided in half:

```text
n
↓
n/2
↓
n/4
↓
n/8
↓
...
↓
1
```

Therefore:

```text
Time  = O(log n)
Space = O(1)
```

### Linear Search vs Binary Search

| Algorithm     | Requirement         |       Time |  Space |
| ------------- | ------------------- | ---------: | -----: |
| Linear Search | No sorting required |     `O(n)` | `O(1)` |
| Binary Search | Sorted array        | `O(log n)` | `O(1)` |

# 🧠 10. How to Analyze Code

When given a new piece of code, follow these steps:

### Step 1: Look for loops

Ask:

> How many times does this loop run?

---

### Step 2: Check whether loops are nested

Nested loops usually multiply:

```text
n × n = O(n²)
```

---

### Step 3: Check whether loops are separate

Separate loops add:

```text
n + n = O(n)
```

---

### Step 4: Look for doubling or halving

For example:

```java
i = i * 2;
```

or:

```java
n = n / 2;
```

Usually indicates:

```text
O(log n)
```

---

### Step 5: Check recursion

Ask:

* How many recursive calls are made?
* How deep does the recursion go?
* Are there multiple recursive branches?

---

### Step 6: Simplify the result

Examples:

```text
O(2n) → O(n)

O(5n + 10) → O(n)

O(n² + n) → O(n²)

O(n³ + n² + n) → O(n³)
```

The dominant growth matters most.

# 📊 11. Complexity Cheat Sheet

| Pattern              |         Time | Typical Extra Space |
| -------------------- | -----------: | ------------------: |
| Single operation     |       `O(1)` |              `O(1)` |
| Single loop          |       `O(n)` |              `O(1)` |
| Separate `n` loops   |       `O(n)` |              `O(1)` |
| Two nested `n` loops |      `O(n²)` |              `O(1)` |
| Doubling / halving   |   `O(log n)` |              `O(1)` |
| `n` × `log n`        | `O(n log n)` |              `O(1)` |
| Linear recursion     |       `O(n)` |              `O(n)` |
| Recursive Fibonacci  |      `O(2ⁿ)` |              `O(n)` |
| Binary Search        |   `O(log n)` |              `O(1)` |

# 📝 Key Lessons

The most important patterns I learned in this phase:

```text
One loop
→ O(n)

Nested loops
→ O(n²)

Separate loops
→ O(n)

Doubling / halving
→ O(log n)

n + log n nested pattern
→ O(n log n)

Linear recursion
→ O(n) time
```

The goal is not to memorize every possible formula.

The goal is to look at code and understand:

> **How does the amount of work and extra memory change when the input `n` becomes larger?**

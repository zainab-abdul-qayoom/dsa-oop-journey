# Two-Pointer Technique — Complete Interview Prep Notes

---

## 1. What is the Two-Pointer Technique? (Simplest Explanation)

Instead of using **one index** to walk through an array one element at a time (and often a nested loop to compare it against every other element — slow, O(n²)), you use **two index variables ("pointers")** that move through the array at the same time. This lets you compare, combine, or rearrange elements in a single pass — usually O(n) instead of O(n²).

Think of it like two people scanning a bookshelf from different ends, walking toward each other, instead of one person checking every book against every other book.

```java
int left = 0;
int right = arr.length - 1;

while (left < right) {
    // do something with arr[left] and arr[right]
    left++;
    right--;
}
```

**Why it's fast:** you touch each element a constant number of times overall, instead of re-scanning the whole array for every single element like a nested loop does.

---

## 2. The Two Main Variations

### Variation A — Opposite Ends (converging pointers)
One pointer starts at index 0, the other at the last index. They move toward each other.

**Used for:** sorted arrays, pair-sum problems, palindrome checks, "max area" style problems.

```java
int left = 0, right = arr.length - 1;
while (left < right) {
    // compare arr[left] and arr[right], then move one or both inward
    left++;
    right--;
}
```

### Variation B — Same Direction (fast/slow pointers)
Both pointers start at (or near) the beginning, but move at different speeds, or one only advances when a condition is met.

**Used for:** removing/overwriting elements in-place, cycle detection (later, in Linked Lists).

```java
int slow = 0;
for (int fast = 0; fast < arr.length; fast++) {
    if (/* some condition on arr[fast] */) {
        // do something using slow, then:
        slow++;
    }
}
```

**How to tell which one you need:** if the array is **sorted** and you're looking for a pair/combination that satisfies a condition → Variation A (opposite ends). If you're **modifying the array in-place** or scanning for a pattern in one direction → Variation B (same direction).

---

## 3. How to Recognize a Two-Pointer Problem (Signal Words)

When reading a problem, these hints suggest two-pointer:

- "sorted array" + "find a pair/triplet that..." → Variation A
- "in-place" + "remove/move elements" → Variation B
- "palindrome" → Variation A (compare from both ends)
- "container", "area", "maximum width between two points" → Variation A
- Anything you could brute-force with a **nested loop comparing pairs** — ask yourself "can I avoid the inner loop by moving pointers smartly instead?"

## 4. Fully Worked Examples (Step-by-Step Reasoning, Not Just Code)

### Example 1 — Move Zeroes (Variation B: same direction)
**Problem:** Move all zeroes in an array to the end, keep other elements in their relative order, in-place.

**Reasoning:**
- `slow` tracks the position where the next non-zero element should go.
- `fast` scans through the whole array.
- Whenever `arr[fast]` is non-zero, swap it into position `slow`, then advance `slow`.

```java
public void moveZeroes(int[] nums) {
    int slow = 0;
    for (int fast = 0; fast < nums.length; fast++) {
        if (nums[fast] != 0) {
            int temp = nums[slow];
            nums[slow] = nums[fast];
            nums[fast] = temp;
            slow++;
        }
    }
}
```
**Dry run on `[0,1,0,3,12]`:**
- fast=0 (val 0): skip
- fast=1 (val 1): swap with slow=0 → `[1,0,0,3,12]`, slow=1
- fast=2 (val 0): skip
- fast=3 (val 3): swap with slow=1 → `[1,3,0,0,12]`, slow=2
- fast=4 (val 12): swap with slow=2 → `[1,3,12,0,0]`, slow=3
- Result: `[1,3,12,0,0]` ✅

### Example 2 — Container With Most Water (Variation A: opposite ends)
**Problem:** Given heights of vertical lines, find two lines that, with the x-axis, form the container holding the most water.

**Reasoning:**
- Start with the widest possible container: `left=0`, `right=last index`.
- Water held = `min(height[left], height[right]) * (right - left)`.
- The **shorter** line is always the bottleneck — moving the taller pointer inward can only keep width smaller with the same (or smaller) height limit, so it can never improve the answer. Moving the **shorter** one might find a taller line and increase area.
- So: always move the pointer at the **shorter** height inward.

```java
public int maxArea(int[] height) {
    int left = 0, right = height.length - 1;
    int maxArea = 0;

    while (left < right) {
        int width = right - left;
        int h = Math.min(height[left], height[right]);
        maxArea = Math.max(maxArea, width * h);

        if (height[left] < height[right]) left++;
        else right--;
    }
    return maxArea;
}
```

### Example 3 — 3Sum (Variation A + a loop)
**Problem:** Find all unique triplets in the array that sum to zero.

**Reasoning:**
- Sort the array first — this is what makes two-pointer possible here.
- Fix one number with a regular loop (`i`), then use two pointers (`left`, `right`) on the remaining part of the array to find pairs that sum to `-nums[i]`.
- Skip duplicate values to avoid duplicate triplets in the answer.

```java
public List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums);
    List<List<Integer>> result = new ArrayList<>();

    for (int i = 0; i < nums.length - 2; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue; // skip duplicate 'i'

        int left = i + 1, right = nums.length - 1;
        while (left < right) {
            int sum = nums[i] + nums[left] + nums[right];
            if (sum == 0) {
                result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                while (left < right && nums[left] == nums[left + 1]) left++; // skip dup
                while (left < right && nums[right] == nums[right - 1]) right--; // skip dup
                left++;
                right--;
            } else if (sum < 0) {
                left++;  // sum too small, need a bigger number
            } else {
                right--; // sum too big, need a smaller number
            }
        }
    }
    return result;
}
```

**Why `sum < 0` means move `left++`:** the array is sorted, so moving `left` forward only increases the sum (bigger number), and moving `right` backward only decreases it. This logic — "if too small, move the pointer that increases the sum; if too big, move the pointer that decreases it" — is the core decision-making pattern behind every opposite-ends two-pointer problem.

## 5. The General Template to Reuse

Whenever you're unsure how to start a two-pointer problem, ask these in order:

1. **Is the array sorted (or can I sort it)?** If yes → likely Variation A.
2. **What does moving `left` do to my answer? What does moving `right` do?** (usually: left increases something, right decreases something)
3. **What's my stopping condition?** (`left < right`, or `fast` reaches the end)
4. **Do I need to skip duplicates?** (common in Sum-family problems)

---

## 6. Common Mistakes People Make

- Using two pointers on an **unsorted** array for a sum/pair problem without sorting first — the "move left if too small, move right if too big" logic only works because the array is sorted.
- Forgetting the `while (left < right)` boundary and letting pointers cross, causing wrong or duplicate results.
- In Sum-family problems, forgetting to **skip duplicate values**, causing duplicate triplets/quadruplets in the output.
- Confusing this with Sliding Window — two-pointer indices move independently and can jump by more than one step in logic; sliding window maintains a *contiguous range* between the pointers and grows/shrinks it. They look similar in code but solve different shapes of problems.
- Not handling the edge case of very small arrays (length 0, 1, or 2) — always sanity check before assuming `left < right` is safely satisfiable.

## 7. Full Interview Q&A

**Q1: What is the two-pointer technique and why is it efficient?**
A: It uses two index variables moving through a data structure simultaneously instead of nested loops, reducing time complexity from O(n²) to O(n) for many array/string problems, since each element is visited a constant number of times overall.

**Q2: What are the two main variations of two-pointer, and when is each used?**
A: Opposite-ends (converging) pointers are used on sorted arrays for pair-sum, palindrome, or container-style problems. Same-direction (fast/slow) pointers are used for in-place array modification or cycle detection.

**Q3: In Container With Most Water, why do we always move the pointer at the shorter height?**
A: Because the shorter line limits the water level regardless of the taller one. Moving the taller pointer inward can only reduce the width while the height limit stays the same or gets worse, so it can never produce a better answer — only moving the shorter pointer has a chance of finding a taller line and increasing the area.

**Q4: Why must the array be sorted before applying two-pointer to sum problems like 3Sum?**
A: Sorting makes the array's values monotonically increase, so moving the left pointer forward reliably increases the sum and moving the right pointer backward reliably decreases it — this is what makes the "which direction to move" decision correct and consistent.

**Q5: How do you avoid duplicate results in problems like 3Sum?**
A: After sorting, skip over repeated values for the fixed index and for both the left and right pointers whenever a valid triplet is found, so the same combination of values isn't added to the result more than once.

**Q6: What's the difference between two-pointer and sliding window?**
A: Two-pointer pointers can move independently and the region between them isn't always meaningful on its own. Sliding window specifically maintains a *contiguous subarray/substring* between the pointers, and the "window" expands or shrinks based on a condition — it's really a specialized form of the same underlying idea.

**Q7: What's the time and space complexity of a typical two-pointer solution?**
A: Usually O(n) time (each pointer moves at most n times total) and O(1) extra space, since no additional data structure is needed — just the two index variables.

## 8. One-Minute Summary (say this out loud before an interview)

"Two-pointer uses two index variables moving through an array or string simultaneously, instead of nested loops, to bring time complexity down from O(n²) to O(n). There are two variations: opposite-ends pointers, used on sorted arrays for pair-sum, palindrome, and container-style problems, where you decide which pointer to move based on whether your current result is too small or too big; and same-direction fast/slow pointers, used for in-place array modification. For sum problems specifically, you sort the array first and skip duplicate values to avoid duplicate results. The core decision-making pattern — move the pointer that could improve your answer — is what generalizes across nearly every two-pointer problem."

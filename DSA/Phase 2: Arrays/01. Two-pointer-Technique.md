# Two-Pointer Technique — Easy Notes (All 3 Examples)

---

## 1. What is Two-Pointer? (Very Simple Explanation)

Normally, to check every pair in an array, we use two loops inside each other. This is slow.

Instead, we use **two variables** called pointers. Each one holds an index (a position number) in the array. Both move through the array **at the same time**. This way we check things much faster — usually in one single pass.

```java
int left = 0;
int right = arr.length - 1;

while (left < right) {
    // do something with arr[left] and arr[right]
    left++;
    right--;
}
```

---

## 2. Two Types of Two-Pointer

### Type A — Start from Both Ends
One pointer starts at the first index (0). The other starts at the last index. They move toward each other, step by step.

**Use this when:** the array is sorted, and you are looking for a pair or group of numbers with some condition. Also used for palindrome checking and "max area" type problems.

### Type B — Both Start Near the Beginning
Both pointers start near the start of the array. One moves faster, or one only moves when a certain condition is true.

**Use this when:** you need to remove or move elements inside the array itself (in-place), or later for cycle detection in linked lists.

**Simple way to decide which type:** 
- Array is sorted + looking for a pair → Type A
- Changing the array in-place, one direction only → Type B

---

## 3. How to Know It's a Two-Pointer Problem

Look for these words/ideas in the problem:

- "sorted array" + "find a pair that..." → Type A
- "in-place" + "remove/move elements" → Type B
- "palindrome" → Type A
- "container", "area", "distance between two points" → Type A
- If you can solve it with a slow nested loop (checking every pair) — ask: "can two pointers do this faster?"

# EXAMPLE 1 — Move Zeroes (Type B)

**Problem:** Move all the zeroes in the array to the end. Keep the other numbers in the same order. Do it in-place (don't make a new array).

```java
public void moveZeroes(int[] nums) {
    int slow = 0;
    for (int fast = 0; fast < nums.length; fast++) {
        if (nums[fast] != 0) {
            int temp = nums[slow];
            nums[slow] = nums[fast];
            nums[fast] = temp;
            slow++;
        }
    }
}
```

## Line-by-Line (Easy Version)

**`int slow = 0;`** — `slow` remembers where the next non-zero number should go.

**`for (int fast = 0; fast < nums.length; fast++)`** — `fast` checks every number in the array, one by one.

**`if (nums[fast] != 0)`** — Only do something if the current number is NOT zero. If it's a zero, just skip it — we don't touch it now.

**`int temp = nums[slow]; nums[slow] = nums[fast]; nums[fast] = temp;`** — This is a simple swap. We swap the value at `slow` with the value at `fast`. This puts the non-zero number in its correct place, and pushes the old value (usually a zero) further ahead.

**`slow++;`** — Now that we placed a number at `slow`, move `slow` one step ahead, ready for the next non-zero number.

## Full Dry Run: `[0, 1, 0, 3, 12]`

| fast | nums[fast] | what we do | array now | slow |
|---|---|---|---|---|
| 0 | 0 | skip | `[0,1,0,3,12]` | 0 |
| 1 | 1 | swap(slow=0, fast=1) | `[1,0,0,3,12]` | 1 |
| 2 | 0 | skip | `[1,0,0,3,12]` | 1 |
| 3 | 3 | swap(slow=1, fast=3) | `[1,3,0,0,12]` | 2 |
| 4 | 12 | swap(slow=2, fast=4) | `[1,3,12,0,0]` | 3 |

**Final answer:** `[1, 3, 12, 0, 0]` ✅

# EXAMPLE 2 — Container With Most Water (Type A)

**Problem:** We have vertical lines of different heights. Pick two lines. Together with the ground, they form a container. Find the two lines that hold the most water.

```java
public int maxArea(int[] height) {
    int left = 0, right = height.length - 1;
    int max = 0;

    while (left < right) {
        int smallestHeight = Math.min(height[left], height[right]);
        int width = right - left;
        int area = smallestHeight * width;

        if (area > max) {
            max = area;
        }

        if (height[left] < height[right]) {
            left++;
        } else {
            right--;
        }
    }
    return max;
}
```

## Line-by-Line (Easy Version)

**`int left = 0, right = height.length - 1;`** — Start with the widest gap: the very first line and the very last line.

**`int max = 0;`** — This will store the biggest water amount we find, out of every pair we check.

**`while (left < right)`** — Keep going as long as the two pointers haven't met. If they meet, there's no space left for a container.

**`int smallestHeight = Math.min(height[left], height[right]);`** — Water can never go higher than the **shorter** line — it would spill over that side. So we always use the shorter line's height.

**`int width = right - left;`** — This is just the distance between the two lines (their positions), not their heights.

**`int area = smallestHeight * width;`** — Water = height × width. Same as finding the area of a rectangle.

**`if (area > max) { max = area; }`** — If this pair gives more water than anything we found before, save it as our new best answer.

**`if (height[left] < height[right]) { left++; } else { right--; }`** — This is the important decision: **always move the shorter line inward.** Why? Because the shorter line is the one limiting our water level. Moving the taller line won't help — the shorter line still limits us, and we'd only make the width smaller. But moving the shorter line gives us a chance to find a taller line and get more water.

## Full Dry Run: `[1, 8, 6, 2, 5, 4, 8, 3, 7]`

| left | right | height[left] | height[right] | smallestHeight | width | area | max | move |
|---|---|---|---|---|---|---|---|---|
| 0 | 8 | 1 | 7 | 1 | 8 | 8 | 8 | left++ (1<7) |
| 1 | 8 | 8 | 7 | 7 | 7 | **49** | **49** | right-- (8 not<7) |
| 1 | 7 | 8 | 3 | 3 | 6 | 18 | 49 | right-- |
| 1 | 6 | 8 | 8 | 8 | 5 | 40 | 49 | right-- (8 not<8) |
| 1 | 5 | 8 | 4 | 4 | 4 | 16 | 49 | right-- |
| 1 | 4 | 8 | 5 | 5 | 3 | 15 | 49 | right-- |
| 1 | 3 | 8 | 2 | 2 | 2 | 4 | 49 | right-- |
| 1 | 2 | 8 | 6 | 6 | 1 | 6 | 49 | right-- |
| loop stops (left < right is now false) | | | | | | | | |

**Final answer:** `49` ✅ — this was found early (second check), and stayed the best answer through the rest.

# EXAMPLE 3 — 3Sum (Type A + one extra loop)

**Problem:** Find all groups of 3 numbers (from 3 different positions) that add up to zero. No repeated groups allowed in the answer.

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> result = new ArrayList<>();

        for (int i = 0; i < nums.length; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            int left = i + 1;
            int right = nums.length - 1;

            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];

                if (sum == 0) {
                    result.add(List.of(nums[i], nums[left], nums[right]));
                    left++;
                    right--;

                    while (left < right && nums[left] == nums[left - 1]) {
                        left++;
                    }
                    while (left < right && nums[right] == nums[right + 1]) {
                        right--;
                    }
                } else if (sum < 0) {
                    left++;
                } else {
                    right--;
                }
            }
        }
        return result;
    }
}
```

## Line-by-Line (Easy Version)

**`Arrays.sort(nums);`** — We sort the array first. This is very important — it's what lets us later say "move left to make the sum bigger" or "move right to make the sum smaller," with confidence that it will work.

**`List<List<Integer>> result = new ArrayList<>();`** — An empty list where we'll save every valid group of 3 numbers we find.

**`for (int i = 0; i < nums.length; i++)`** — This is the **outer loop**. It picks one number at a time to be the "first number" of the group. For each one, we search the rest of the array (using two pointers) for two more numbers that add up with it to zero.

**`if (i > 0 && nums[i] == nums[i - 1]) { continue; }`** — If this number is the same as the one right before it, skip it. We already tried every possible group starting with that same value in the previous round — trying it again would just give us the same groups again.

**`int left = i + 1; int right = nums.length - 1;`** — Set up two pointers, starting right after `i`, all the way to the end of the array.

**`while (left < right)`** — Keep going as long as the pointers haven't met.

**`int sum = nums[i] + nums[left] + nums[right];`** — Add up the 3 current numbers.

**`if (sum == 0) { ... }`** — We found a valid group! Save it — but a bit more work is needed after (explained below).

**`else if (sum < 0) { left++; }`** — The sum is too small. Since the array is sorted, moving `left` forward gives us a bigger number, which makes the sum bigger too — closer to zero.

**`else { right--; }`** — The sum is too big. Moving `right` backward gives us a smaller number, which makes the sum smaller — closer to zero.

**Inside the "sum == 0" part:**

**`result.add(List.of(nums[i], nums[left], nums[right]));`** — Save this group of 3 numbers.

**`left++; right--;`** — Move both pointers inward. If we used the same numbers again, we'd just find the same group again — so we move on to search for new groups.

**`while (left < right && nums[left] == nums[left - 1]) { left++; }`** — After moving, check: is this new `left` number the same as the one we just used? If yes, skip past it — using it again would give us a duplicate group.

**`while (left < right && nums[right] == nums[right + 1]) { right--; }`** — Same idea, but for `right`. We check against the number we just moved away from (since `right` moves backward, not forward).

## Full Dry Run: `[-1, 0, 1, 2, -1, -4]`

**After sorting:** `[-4, -1, -1, 0, 1, 2]`
```
Index:   0   1   2   3  4  5
Value:  -4  -1  -1   0  1  2
```

**i = 0 (nums[i] = -4):**
| left | right | sum | what happens |
|---|---|---|---|
| 1(-1) | 5(2) | -4-1+2=-3 | too small → left++ |
| 2(-1) | 5(2) | -4-1+2=-3 | too small → left++ |
| 3(0) | 5(2) | -4+0+2=-2 | too small → left++ |
| 4(1) | 5(2) | -4+1+2=-1 | too small → left++ |
| 5 | 5 | loop stops | |

**i = 1 (nums[i] = -1):**
| left | right | sum | what happens |
|---|---|---|---|
| 2(-1) | 5(2) | -1-1+2=0 ✅ | save `[-1,-1,2]` → left=3, right=4. No repeats found, so no skipping needed. |
| 3(0) | 4(1) | -1+0+1=0 ✅ | save `[-1,0,1]` → left=4, right=3 → loop stops |

**i = 2 (nums[i] = -1):** same number as `nums[1]` → **skip it** (it's a repeat)

**i = 3 (nums[i] = 0):**
| left | right | sum | what happens |
|---|---|---|---|
| 4(1) | 5(2) | 0+1+2=3 | too big → right-- |
| 4 | 4 | loop stops | |

**i = 4, i = 5:** not enough space left for a group of 3 → loop stops right away.

**Final answer:** `[[-1,-1,2], [-1,0,1]]` ✅ — this matches the correct answer, with no repeated groups.

## 4. Simple Checklist to Use When Stuck

1. **Is the array sorted (or can I sort it)?** If yes → probably Type A.
2. **What happens if I move `left`? What happens if I move `right`?** (usually: one makes the answer bigger, the other makes it smaller)
3. **When should the loop stop?** (`left < right`, or `fast` reaches the end of the array)
4. **Do I need to skip repeated numbers?** (common in "sum" problems — check in up to 3 places: the outer loop, and both pointers after finding a match)

---

## 5. Common Mistakes to Avoid

- Using two-pointer on an array that is **not sorted** (for sum/pair problems) without sorting it first.
- Letting the pointers cross without checking `left < right` — this causes wrong or repeated answers.
- Forgetting to skip repeated numbers in sum problems — causes duplicate groups in the answer.
- Calculating the area/width/height **after** moving a pointer instead of **before** — this mixes up numbers from two different pairs.
- Using a `for` loop when a pointer is also being changed by hand inside it — this can move that pointer twice by mistake. Use `while(left < right)` instead.
- Mixing up two-pointer with sliding window — they look similar, but two-pointer moves each pointer independently, while sliding window keeps a *connected block* of numbers between the pointers that grows or shrinks.

---

## 6. One-Minute Summary (say this before an interview)

"Two-pointer uses two index variables moving through the array at the same time, instead of two nested loops. This makes the code much faster. Starting from both ends works for sorted arrays — pair-sum problems, palindromes, and container-style problems — where we decide which pointer to move based on whether our current answer is too small or too big. Starting both pointers near the beginning, at different speeds, works for changing the array in-place. For problems with 3 or more numbers, like 3Sum, we use an extra loop for the first number, sort the array first, and then use two-pointer for the last two numbers — remembering to skip repeated numbers so we don't get duplicate answers."
